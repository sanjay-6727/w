# Two-Collection CRUD Template (Spring Boot + MongoDB + Vue)

A beginner-friendly template you can copy for projects that have **two MongoDB collections**, such as:
- Student + Course
- Author + Book
- Department + Employee
- Movie + Booking

It uses ordinary repository methods and Java code, not MongoDB aggregation pipelines. The second collection stores the ID of a document in the first collection.

## What the template does

### First collection
- Add, list, update and delete first items.
- Search by name and filter by category.
- Sort by numeric value.
- Show first items that have related second items.
- Show first items that have no related second items.

### Second collection
- Add, list, update and delete second items.
- Search by person/customer name.
- Show second items connected to a selected first item.
- Each second item stores `firstItemId`.

### Reports
- Counts for both collections.
- Total numeric value from the second collection.
- Average, minimum and maximum first-item price/value.
- Related-item count and numeric total by first item.

## 1. Run the backend

Open `backend` in IntelliJ as a Maven project. Ensure Java 17 and MongoDB are installed/running.

The sample API uses `http://localhost:8080/api`.

Run `TwoCollectionApplication.java`.

## 2. Run the frontend

Install Node.js if needed. Open a terminal in `frontend`:

```bash
npm install
npm run dev
```

Open the URL Vite prints, usually `http://localhost:5173`.

## 3. How to reuse it for another project

Use the names below as placeholders:

| Template name | Replace with your project |
|---|---|
| `FirstItem` | Main collection model, e.g. `Student` |
| `SecondItem` | Related collection model, e.g. `Enrollment` |
| `firstItems` | Main collection |
| `secondItems` | Related collection |
| `name` | Main item's display name |
| `category` | A text field such as department, genre, type |
| `price` | A number field such as fee, salary, amount |
| `personName` | Related item's person field, e.g. student name |
| `value` | A number field to total, e.g. seats, quantity, marks |
| `firstItemId` | The ID that connects a related document to a main document |

If your real fields have different names, update the Java models, controller/service/repository code, and Vue form fields to match. Keep the JSON field names in Java and Vue consistent.

## 4. Change the names in your project

For a **Student + Enrollment** project, for example:
- `FirstItem` becomes `Student`.
- `SecondItem` becomes `Enrollment`.
- `firstItemId` becomes `studentId`.
- `name` becomes `studentName`.
- `category` might become `department`.
- `price` might become `fee`.
- `personName` might become `studentName` or `enrolledBy`.
- `value` might become `credits` or `marks`.

Change class/file names, collection names, Java field names, endpoint paths, and frontend labels consistently. This is a learning template rather than a universal generator.

## Note about CORS

`CorsConfig.java` allows the Vue development server at `http://localhost:5173`. If you prefer the annotation method, you can instead add this above the controller class:

```java
@CrossOrigin(origins = "http://localhost:5173")
```

and import `org.springframework.web.bind.annotation.CrossOrigin`. Avoid configuring both unless you have a reason.

## Notes

- This template deliberately keeps the code simple and readable.
- IDs are MongoDB document IDs generated by Spring Data.
- Deleting a first item also deletes related second items in this example.
- The report calculations are done in Java streams, not MongoDB aggregation.
- Adjust validation and error handling for a real production application.
